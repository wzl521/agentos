# OryxOS 是什么

OryxOS 是一个**基于 Java 实现的面向企业场景的 Agent OS（智能体操作系统）**。

它装在企业自己的 K8s 或服务器上，作为统一底座，在底座上跑各种业务 Agent——运维助手、客服助手、HR 助手、销售助手、知识管理助手——共享一套渠道接入、模型路由、工具调用、记忆系统、沙箱执行能力。

**数据完全留在企业自己的基础设施，不锁任何云生态。**

## 它解决什么问题

今天企业落地 AI Agent 的瓶颈不在模型能力，而在工程底座。单个 Agent 做出 demo 很容易，但一旦要跑在生产环境、服务全公司，就撞上一堆问题：

- **数据往哪放**——核心业务数据不能出企业
- **怎么跟现有系统对接**——ERP、CRM、CMDB 都是 Java 体系
- **怎么审计**——谁、在什么时候、让 Agent 做了什么，必须可追溯
- **怎么管权限**——不能让客服 Agent 拿到能 `rm -rf` 的 Shell Tool

OryxOS 解决的就是这层问题。它把渠道接入、模型路由、记忆、工具、沙箱这些公共能力下沉到底座，**业务方之上只需要配 Agent、写 Tool，上一个新 Agent 不用重复造这些轮子。**

对于严监管行业（金融、政务、电信、能源、医疗），这件事更刚性——数据不能出企业、系统必须完全可审计、新组件要过现有合规流程、技术栈要跟 Java 体系对齐。OryxOS 就是为这个场景设计的。

## 核心理念

### 业务方不写 Agent 后端代码

业务方只做两件事：

1. **写一个 Tool** 实现某个具体功能（可以用任何语言，通过 MCP 协议暴露）
2. **配置一个 Agent** 把这个 Tool 用起来（一份 Profile YAML）

Agent 是配置出来的，不是写代码写出来的。消息从哪来、LLM 怎么调、上下文怎么续、审计怎么落，都是 OryxOS 的事。

### 核心阶段交付运行时内核

OryxOS 的交付分两段：

- **核心阶段**：先把 Agent OS 的运行时内核用 Java 做扎实，对齐业界开源 Agent OS 的基础层
- **扩展阶段**：真正的差异化治理层（多租户、SSO、完整审计、Tool 治理）陆续补齐

核心阶段是地基，企业级治理是终局。

## 与其他项目的关系

| 项目 | 是什么 | 与 OryxOS 的关系 |
|------|--------|-----------------|
| OpenClaw（Node.js） | 个人/小团队的 Agent OS | 同类不同定位，通过 SKILL.md 互通 |
| Hermes Agent（Python） | 偏团队和企业的 Agent OS | 同类不同定位，通过 SKILL.md 互通 |
| Dify、Coze | 可视化工作流编排平台 | 互补，可跑在 OryxOS 之上，拿它当后端 |
| Spring AI、LangChain4j | LLM 调用框架 | 被 OryxOS 复用，做底层 LLM 调用 |

一句话定位：**OryxOS 既不跟编排平台抢上层，也不跟框架抢底层，而是守在中间这一层——让 Agent 能常驻、可治理、可审计地跑起来的底座。**

## 四个关键词

**统一、私有、易接入、可观测。**

- **统一**：企业内多个业务 Agent 共享同一套底座
- **私有**：数据和部署完全在企业自己手里
- **易接入**：标准 Spring Boot 工程结构，跟现有系统直接对接
- **可观测**：标准 Prometheus 指标、结构化日志、健康检查
